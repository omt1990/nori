# NORI 設計 v1.1（2026-10-13 オーナー承認）

図解版：https://claude.ai/artifact/APMkqf1YSPsoaLdUbGjs5F

設計の基準：**記録が消えない／運営の手が要らない／説明なしで遊べる**。

## 1. 仕組み

```
GitHub omt1990/nori ──push──▶ Vercel（omt1990）──▶ スマホのブラウザ（1ページのアプリ）
                                                        │
                                                        ▼
                                              Firebase RTDB（新プロジェクト nori・匿名認証）
写真：LINE のまま。アプリは保存しない
```

- サーバーのコードなし。手動のデプロイなし
- RTDB は地下で切れた書き込みを端末にためて、戻ったら自動で送る（この用途で Supabase より有利）
- 名前は部屋の中だけ。部屋は作成から30日で読めなくなる（ルールで `now < createdAt + 30d`）

## 2. 記録の持ち方（最重要）

**出来事（イベント）を追記するだけ。消さない・書き換えない。**

```
rooms/{code}/
  config        作成時に1回だけ書く（時間・路線・お題あり/なし・盤・チーム一覧・createdAt）
  startedAt     「開始」で1回だけ書く（サーバー時刻）
  events/{pushId}
    {type, team, uid, at, ...}
    type: join | start | draw | arrive | mission | void | 
```

- 盤・得点・ログ・残り時間は、各端末が `config + startedAt + events` から計算する
- 同時に押しても消えない（push は衝突しない）
- 間違えたら `void`（対象 event の id を指す）を足す。元は残る
- 終了は `startedAt + config.duration`。誰も開いていなくても終わる。終了後の event はルールで拒否する
- ルール（database.rules.json）：`config`/`startedAt` は存在しなければ書ける・あれば書けない。`events` は追加のみ・更新削除不可・`at` はサーバー時刻・終了後は不可

## 3. 画面（4つ）

| 画面 | 入力 | 出る |
|---|---|---|
| 作る | 時間（2h/4h/8h）・路線・お題あり/なし | 参加リンク（`?room=XXXXXX`）。作った人も参加者の1人 |
| 参加 | 名前・チーム（自分で選ぶ。人数は表示） | — |
| プレイ | カードを引く（アプリ／手持ちなら出た数を押す）・着いた駅・お題 | 盤・残り時間・ログ・相手の盤（終盤は隠す） |
| 結果 | — | 順位・優勝・各チームの盤・X に投稿 |

- **運営という役割はない。**承認・チーム分け・手動終了の画面はない
- 「開始」は参加者の誰が押してもよい（条件：2チーム以上に1人ずつ）

## 4. 時間で決まるもの

| | 2時間 | 4時間 | 8時間 |
|---|---|---|---|
| 駅の盤 | 3×3（8駅＋FREE） | 4×4（16駅） | 5×5（24駅＋FREE） |
| 路線 | 1〜2本を選ぶ | 3〜4本を選ぶ | 全部 |
| お題 | 盤なし・達成数で加点 | 3×3 | 4×4 |
| 相手の盤を隠す | 最後の20分 | 最後の40分 | 最後の80分 |

- 盤は選んだ路線の駅だけから作る → 「盤にない駅に着いた」が起きない
- 駅データ：国土数値情報 N02-24（都内全駅・乗り入れ路線つき）。ORI と同じ出典。
  抽出スクリプトの原型は ORI 用 `extract.py`（セッション scratchpad。再作成可）

## 5. ルール（決定）

| 項目 | 決定 |
|---|---|
| カード | アプリでも手持ちのトランプでもよい。手持ちのときは出た数を押す。どちらも event に残る |
| 札の数 | A=1　2〜10=その数　J=11　Q=12　K=13　JOKER=今いる路線の好きな駅 |
| 移動 | 上りか下り、出た数だけ。端で折り返す |
| 乗り換え | 自由 |
| 到着 | 着いた駅を押す。前に来た駅でもよい。盤は1回だけ埋まる |
| お題 | 1回の到着につき1つ。同じ駅に戻ればまたできる |
| 得点 | 駅pt × (お題pt + 1)。駅pt＝盤の到着マス＋ビンゴ列×3、お題pt＝達成数＋ビンゴ列×3 |
| 終了 | 開始＋選んだ時間。自動 |
| 相手の盤 | 終盤は隠す（§4） |
| お題の中身 | 旧24件は引き継がず、Tokyo On Foot の目的（まだ知らない東京）に沿って作り直す。別の回で |

## 6. 旧アプリから引き継がないもの

主催者/プレイヤーの分離・承認待ち・チーム割り当て・状態ボタン（募集中/編成中）・ゴールペナルティ・開始終了時刻の入力・
